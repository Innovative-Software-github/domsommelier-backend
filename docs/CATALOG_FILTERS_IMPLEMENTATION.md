# Фильтры расширенного каталога — этап 2

Реализовано локально 12 сентября 2026 года. Требуется модель и миграция из [первого этапа](PRODUCT_ATTRIBUTES_IMPLEMENTATION.md). Импорт товаров и выкладка на сервер этим этапом не выполнялись.

## Что видит покупатель

Общие существующие фильтры (страна, цена, производитель, объём, цвет, сахар, тип напитка) сохраняются. Добавлены:

| Раздел | Фильтры |
|---|---|
| Все категории | Бренд |
| Вино, игристое, крепкие | Регион, аппелласьон, ёмкость выдержки из `aging.vessels` |
| Вино | Крепость; год урожая из существующего поля; сорта с подписями нового справочника и поддержкой старых значений |
| Игристое | Крепость, сортовой состав, год урожая, метод производства |
| Только виски | Тип виски, стиль купажа, заявленный возраст |
| Только коньяк | Возрастная классификация, заявленный возраст, зона происхождения |

Зависимые фильтры показываются только при выборе одного соответствующего типа в категории `spirit`. Если выбрать несколько типов или «Все», остаются общие поля. При смене типа несовместимые условия удаляются из состояния, URL при применении и серверного запроса. Это предотвращает скрытое ограничение коньяка ранее выбранным возрастом виски.

Поля и варианты без данных не предлагаются. Справочные варианты берутся из характеристик существующих товаров, а не из всего справочника. Границы диапазонов вычисляются по известным значениям; отсутствие возраста не становится нулём. Границы относятся ко всему разделу каталога. Счётчики вариантов учитывают выбранный город и остальные условия; варианты с нулём скрываются, кроме уже выбранных.

Счётчики основного типа напитка игнорируют зависимые условия виски/коньяка, чтобы покупатель мог переключить тип. Выбранный вариант сохраняется в интерфейсе даже при отсутствии в свежей конфигурации — его можно снять.

## API и совместимость

URL конфигурации и поиска сохранены. `GET /api/v1/filters` и категорийные маршруты возвращают конфигурацию, дополненную текущими данными каталога. Новые определения не нужно вручную добавлять в таблицу `filter`.

Дополнительные свойства конфигурации:

- `selectionMode: "value"`: в запрос и URL передаётся `option.value`, в интерфейсе показывается `option.label`. Для прежних полей без этого признака сохраняется контракт по подписи.
- `subtype: "whisky" | "cognac" | null`: зависимость от выбранного типа крепкого напитка.

Ключи новых запросов: `brand`, `region`, `appellation`, `agingVessel`, `strength`, `year`, `grapeComposition` (игристое), `sparklingMethod`, `whiskyType`, `whiskyBlendStyle`, `whiskyAge`, `cognacClassification`, `cognacAge`, `cognacOrigin`.

Списки внутри одного поля объединяются по OR, разные поля — по AND. Диапазоны: `[min, max]`, границы включены, любая граница может быть `null`. Например:

```json
{
  "subcategory": ["Виски"],
  "whiskyType": ["single_malt"],
  "whiskyAge": [10, null],
  "brand": ["example_brand"]
}
```

Для вина сохраняется ключ `grape`: конфигурация теперь отдаёт стабильные коды и подписи из справочника с запасным переводом старых кодов. Старые русские названия известных сортов в запросах продолжают поддерживаться. Счётчики содержат коды и прежние переведённые подписи. Выбор нескольких сортов одного вина не создаёт дубликаты в выдаче.

Старые товары без новых характеристик остаются в выдаче без соответствующих фильтров; при выборе новой характеристики неизвестные значения не совпадают. URL сохраняет пустые границы и нули, а цифровые коды справочников не преобразует в числа. Назад/вперёд в браузере восстанавливает состояние фильтров из URL.

## Реализация и индексы

`CatalogFilterFields` — фиксированный реестр полей, JSON-путей, типов и зависимостей. `CatalogAttributePredicates` строит Criteria-предикаты по нему. Параметры не используются как SQL-идентификаторы; значения для JSONPath экранируются JSON-сериализатором.

Скалярные характеристики используют `jsonb_extract_path_text`. Списки используют JSONPath-проверку существования совпадения; для счётчиков элементы разворачиваются в БД с `count(distinct product)`. Товары целиком для подсчёта в память приложения не загружаются. Неактивные зависимые фасеты не считаются.

`20260912_catalog_filter_indexes.sql` добавляет индексы выражений для бренда, региона, аппелласьона, метода игристого и справочных полей виски/коньяка. Индексы не ускоряют автоматически все запросы по массивам или числовым диапазонам. Массовый импорт должен сопровождаться проверкой планов и скорости на фактическом объёме каталога. Конфигурация при чтении выполняет запросы по данным; нагрузочное тестирование на объёме продакшена не проводилось.

## Выкладка

1. Выполнить миграцию характеристик из этапа 1, если она ещё не применялась.
2. Выполнить `infrastructure/db/migrations/20260912_catalog_filter_indexes.sql` через `psql` с `ON_ERROR_STOP=1`. Миграция повторяема; построение индексов планировать в подходящее окно обновления.
3. Выложить backend, затем storefront. Админка этапа 1 нужна для заполнения характеристик.
4. Проверить товар с новыми полями, фильтрацию, смену виски/коньяк, счётчики по городу и прямую ссылку на выбранные фильтры.

## Проверки

Backend: 5 интеграционных тестов на временной PostgreSQL с настоящими entity и Hibernate + 9 регрессионных тестов DTO. Проверены скалярные значения, диапазоны с пустой границей, массивы и OR, экранирование, счётчики, смена типа, городские остатки, старые сорта, реальные подписи/границы и двукратное применение SQL индексов.

Интеграционный тест создаёт и удаляет схему. Использовать только отдельную временную БД с именем, заканчивающимся на `_test`:

```sh
./mvnw -Dtest=CatalogFiltersPostgresTest,CatalogAttributesTest,CatalogWriteCompatibilityTest,CatalogReferenceTest \
  -Dcatalog.filters.postgres.url=jdbc:postgresql://127.0.0.1:55439/catalog_filters_test test
```

Storefront:

```sh
node --test tests/catalog-filters.test.cjs
./node_modules/.bin/tsc --noEmit --incremental false
```

6 тестов: зависимости, совместимость кодов/подписей, URL с `null`/нулём, цифровые коды, устаревшие условия и некорректные диапазоны. Дополнительно в браузере проверена изолированная страница `tests/catalog-filters-preview.html` с настоящими компонентами: выбор виски, отправляемый код, скрытие варианта с нулём, переключение на два типа и на коньяк, выбор VSOP. Фикстура не обращается к настоящему каталогу и не является production-маршрутом Next.js.
