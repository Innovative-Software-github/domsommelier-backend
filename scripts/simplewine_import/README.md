# Импорт SimpleWine

Отдельный скрипт для воспроизводимой подготовки и создания карточек. Python 3.9+. Базовые команды используют стандартную библиотеку; режим fetch --browser требует Playwright и установленный Google Chrome. Существующий `scripts/catalog_generator` не изменяется и не вызывается: этот импорт не генерирует тексты/фото, не запрашивает OTP и не отправляет письма.

## Текущее состояние проверки

12 сентября 2026 года прямое скачивание всех четырёх заданных страниц вернуло HTTP 403. Загрузчик сохранил статусы отказа; защиту сайта не обходит и автоматически 403/429 не повторяет. Поэтому массовый онлайн-парсинг в текущей среде пока недоступен.

Для проверки преобразования подготовлены короткие фактические выдержки из доступного индексированного представления **именно этих четырёх ссылок**. Это ручные транскрипции структурированных характеристик, а не загруженный исходный HTML. Они помечены `indexed_factual_excerpt` и используются только с `--allow-snapshots`:

- [Paddle Creek, 160429](https://simplewine.ru/catalog/product/paddle_creek_sauvignon_blanc_2025_075_160429/)
- [Bruni Prosecco, 160963](https://simplewine.ru/catalog/product/prosecco_brut_075_160963/)
- [Bellevoye, 141968](https://simplewine.ru/catalog/product/bellevoye_finition_grain_fin_07_gift_141968/)
- [Camus, 156688](https://simplewine.ru/catalog/product/camus_ile_de_re_fine_island_07_gift_156688/)

План из четырёх карточек подготовлен. Запись не выполнялась: не заданы наши артикулы/цены и не подтверждена проверка карточек. На доступном реальном HTML адаптер ещё не проверен — только на HTML-фикстуре и фактических выдержках. Перед массовым запуском нужно получить доступный источник HTML/выгрузку и проверить адаптер на его реальной разметке.

## Быстрый запуск

Из каталога backend:

```sh
python3 scripts/simplewine_import/importer.py fetch \
  --input scripts/simplewine_import/examples/batch.json \
  --raw-dir scripts/simplewine_import/work/raw

python3 scripts/simplewine_import/importer.py prepare \
  --input scripts/simplewine_import/examples/batch.json \
  --dictionary scripts/simplewine_import/examples/references.json \
  --raw-dir scripts/simplewine_import/work/raw \
  --allow-snapshots \
  --out scripts/simplewine_import/work/plan.json

python3 scripts/simplewine_import/importer.py import \
  --plan scripts/simplewine_import/work/plan.json \
  --dry-run \
  --report scripts/simplewine_import/work/dry-run.json
```

`prepare` создаёт JSON и соседний Markdown для просмотра: `work/plan.json`, `work/plan.md`. `fetch` при 403 завершится с кодом 2; следующая команда с явным `--allow-snapshots` работает отдельно. Успешно загруженные HTML кэшируются с SHA-256; `--refresh` запрашивает заново. Между запросами пауза 2 секунды, размер ответа ограничен 8 МБ, таймаут 30 секунд. Перенаправления не выполняются автоматически.

## Что заполнять

Скопировать `examples/batch.json` в рабочий файл рядом с ним (или поправить пути `snapshot` относительно нового файла). Для каждого товара:

- `article` — **наш** артикул; внешний номер хранится отдельно в `source.externalId`.
- `initialPrice` — поле «Начальная цена» нашей админки, положительное число.
- `price` — наша розничная цена, положительное число.
- `reviewed: true` — после сверки полей, источника и замечаний.
- `overrides` — явные исправления полей нашего DTO; вложенные объекты объединяются, списки заменяются. Например, название или подтверждённая подкатегория по справочнику сервера.

После любых правок выполнить `prepare` заново. Редактирование готового `plan.json` обнаруживается хешем, повторная подготовка сохраняет проверяемый источник изменений. Статус `reviewed` относится ко всей карточке вместе с её замечаниями; неизвестные необязательные значения можно оставить `null`.

Цены источника, остатки и полные рекламные описания автоматически не переносятся. Фото доступны через отдельную команду photos (ниже). Из текстовых упоминаний не выводятся возраст, винтаж, ароматические теги и границы вкусовой шкалы. Винтаж игристого и возраст коньяка из противоречивого описания оставлены пустыми. Доступный табличный срок выдержки для крепкого используется только как явно указанный возраст. Для вкусовых оценок принята единая шкала 1–5; границы проставляются автоматически, источник сохраняется.

## Справочники

`examples/references.json` — явное сопоставление подписей источника и наших `{code, label}` по виду справочника. Неизвестное соответствие блокирует импорт до заполнения этой карты. Скрипт не генерирует новые коды автоматически из произвольной транслитерации.

Перед записью API проверяет базовые страны/цвета/типы и т. п. Они должны уже существовать: при несовпадении скрипт предлагает исправить DTO через `overrides`. Новые справочники характеристик создаются через отдельный API:

- Совпало название, код отличается — переиспользуется существующий код и каноническая подпись.
- Совпал код, но название другое — импорт блокируется.
- Нет ни кода, ни названия — планируется создание.
- Конфликт параллельного создания (409) — повторно читается справочник.

## Запись через API

Используется `ADMIN_TOKEN` из окружения — токен **существующей админской сессии**. Скрипт не сохраняет и не печатает его. Без токена `dry-run` выполняет только локальную проверку и явно пишет, что API не проверен. При заполненных полях и заданном токене сначала запустить тот же `import --dry-run`: он проверит API, базовые справочники, совпадения артикулов и покажет план создания, не отправляя POST.

После проверки запуск записи — отдельная команда:

```sh
python3 scripts/simplewine_import/importer.py import \
  --plan scripts/simplewine_import/work/plan.json \
  --api http://localhost:8080 \
  --state scripts/simplewine_import/work/import-state.json \
  --report scripts/simplewine_import/work/import-report.json \
  --apply
```

Один незаполненный товар блокирует запись всей партии на этапе предварительной проверки. После её прохождения справочники и товары создаются последовательными API-запросами. Это не единая транзакция партии: при ошибке ранее созданные объекты остаются; результат фиксируется в отчёте и журнале.

## Повторный запуск и дубликаты

Журнал `import-state.json` связывает адрес API + внешний ID + наш артикул + ID созданного товара. Один журнал защищён файловой блокировкой от параллельных процессов. Успешно созданные товары при повторном запуске проверяются по ID и пропускаются, изменения плана автоматически не перезаписывают карточку.

Перед первым созданием точный артикул проверяется по всем категориям с пагинацией. Если он уже существует без записи в журнале, операция блокируется — скрипт не присваивает себе чужой товар. Справочники проверяются отдельно.

**При таймауте POST запись остаётся `pending`. Второй POST автоматически не отправляется**, даже если поиск пока не нашёл товар. Нужно проверить фактический результат в админке. Если товар создан, после сверки артикула/категории внести его `productId` и `status: "created"` в соответствующую запись журнала. Если достоверно установлено, что записи не было, удалить только эту `pending`-запись и повторить проверку. При неопределённости не сбрасывать журнал.

Не удалять рабочий журнал и использовать один его путь для всех запусков партии. Между разными компьютерами/разными журналами атомарная блокировка не обеспечивается: в текущем API нет серверного idempotency key и глобальной уникальности артикула. Для параллельного массового импорта потребуется отдельное серверное расширение.

## Проверки

```sh
python3 -m unittest discover -s scripts/simplewine_import/tests -v
./mvnw -Dtest=SimpleWineImportContractTest \
  -Dsimplewine.plan=scripts/simplewine_import/work/plan.json test
```

15 Python-тестов: четыре категории, `null`, год/возраст без догадок, извлечение HTML, артикул/домен, блокировка незаполненной партии, dry-run, повторный запуск, таймаут после успешного создания, конфликт артикула, переиспользование и конфликт справочника, хеш плана и файловая блокировка. Для сценариев API используется тестовый двойник, не рабочая БД.

4 Java-проверки читают подготовленные payload и валидируют их настоящими DTO/Jakarta Validator. Недостающие цены и артикулы подставляются только в памяти теста; в файлы партии и каталог они не записываются. Авторизованное создание на работающем API ещё не проверено — для него нужны наши цены, артикулы и существующая сессия администратора.

## Фотографии

Из папки backend, после успешного `fetch`, скачать фотографии локально:

```sh
python3 scripts/simplewine_import/importer.py photos \
  --input scripts/wines-10.json \
  --raw-dir scripts/simplewine_import/work/raw \
  --photo-dir scripts/simplewine_import/work/photos \
  --report scripts/simplewine_import/work/photo-report.json
```

Команда читает Product JSON-LD (с проверкой артикула, если он указан), либо главное фото `og:image`. Она не собирает все картинки страницы. JSON-LD может содержать галерею; og:image обычно даёт только главное фото. Если HTML недоступен или фото не обнаружены, добавьте в запись товара `photoUrls` — массив фактических прямых HTTPS-ссылок на изображения этого товара на static.simplewine.ru. Тогда HTML для команды photos не нужен. Сверяйте фото и винтаж перед загрузкой.

После импорта товаров и при заданном ADMIN_TOKEN загрузить фото в MinIO через API:

```sh
python3 scripts/simplewine_import/importer.py photos \
  --input scripts/wines-10.json \
  --raw-dir scripts/simplewine_import/work/raw \
  --photo-dir scripts/simplewine_import/work/photos \
  --api http://localhost:8080 \
  --state scripts/simplewine_import/work/wines-10-state.json \
  --report scripts/simplewine_import/work/photo-report.json \
  --apply
```

Обязательно используйте тот же state-файл, что при импорте товаров. Команда проверяет ID, артикул и категорию и отправляет multipart `files` в `POST /products/files/upload?productId=...`. Бэкенд сохраняет фото в MinIO и привязывает к товару. Все файлы скачиваются и товары проверяются до первой загрузки. Без `--apply` API и журнал не изменяются. Токен не передаётся SimpleWine. Карточки и флаг reviewed эта команда не меняет.

Поддерживаются JPEG/PNG/WebP до 10 МиБ (лимит бэкенда; запрос до 11 МиБ) и до 20 ссылок на товар. Проверяются сигнатура и Content-Type, полноценного декодирования нет. Разрешены только HTTPS-хосты SimpleWine; редиректы и автоматические повторы 403/429 отключены. Пауза между файлами 2 секунды (`--delay`). Кэш проверяется SHA-256. Идентичные файлы в одной карточке объединяются.

Журнал хранит хеши фото внутри записи товара. Успешные загрузки пропускаются при повторе. При ошибке POST сохраняется `photos.<sha256>.status = "pending"`, повторная отправка блокируется. Проверьте результат в админке по имени `simplewine-<sha256>.<ext>`: если фото привязано, после сверки установите статус `uploaded`; если достоверно не привязано, удалите только эту pending-запись. При неопределённости журнал не сбрасывайте. Фото из другого журнала/ручной загрузки не распознаются. Удалённое вручную фото со статусом uploaded автоматически не восстанавливается.

Проверено 24 Python-теста, включая 9 проверок фотографий: извлечение, домены, размер, кэш, отсутствие токена в запросах источнику, режим без записи, повторы, таймаут и multipart-контракт. Адаптер фотографий проверен на фикстурах; реальная галерея и запись через работающий API пока не проверены.

## Если обычный fetch возвращает 403

Доступен отдельный режим видимого Google Chrome (установленного на компьютере). Используется временный профиль, без доступа к личным cookies и без маскировки автоматизации. Отказ 403/429 не обходится: браузерный запуск при отказе останавливает партию. Успешное открытие через другой браузер само по себе не гарантирует работу этого режима.

Однократная установка из каталога backend:

```sh
python3 -m venv scripts/simplewine_import/.venv
scripts/simplewine_import/.venv/bin/pip install -r scripts/simplewine_import/requirements-browser.txt
```

Проверка первой карточки:

```sh
scripts/simplewine_import/.venv/bin/python scripts/simplewine_import/importer.py fetch \
  --input scripts/wines-10.json \
  --raw-dir scripts/simplewine_import/work/raw \
  --browser --limit 1
```

Для всей партии уберите `--limit 1`. Откроется отдельное окно Chrome; не закрывайте его до завершения. Сохранённый DOM проверяется по заголовку/артикулу и хешируется. Формат кэша совместим с `prepare` и `photos`. Уже сохранённые корректные страницы пропускаются. При ошибке отчёт содержит только обработанные позиции, остальные не запрашиваются. Браузерный режим не подтверждает возраст/согласия и не решает CAPTCHA. Если требуется ручное действие, остановите запуск и используйте разрешённую выгрузку или сохранённые страницы с отдельной проверкой источника.

Проверка 2026-09-12: браузерный fetch на установленном Chrome успешно сохранил все 10 карточек из scripts/wines-10.json. Повторный запуск переиспользовал первую карточку по SHA-256. На реальном DOM первой карточки прошла проверка артикула и обнаружена одна ссылка фото. Это подтверждает загрузку страниц, но ещё не полноту характеристик/галереи или запись партии в API. Всего 27 Python-тестов прошли, включая браузерный кэш-формат, отказ 403 и несовпадение артикула.


Если photos получает HTTP 403, запустите тот же набор аргументов через `scripts/simplewine_import/.venv/bin/python` с флагом `--browser`. Открывается отдельный Chrome; существующие корректные файлы берутся из кэша. При отказе браузера запрос не повторяется. Проверка 2026-09-12: скачаны главные фотографии всех 10 вин, без записи в API. Лимит файла увеличен до 10 МиБ в скрипте, application.yml и Docker Compose; для применения в других окружениях нужно перезапустить приложение с новой конфигурацией. Браузер получает тело ответа изображения целиком, затем проверяет размер (при наличии Content-Length проверяет до чтения).


Единая шкала оценок: по решению владельца каталога минимум 1, максимум 5. В админке поля границ скрыты, значение ограничено 1–5; при сохранении границы добавляются автоматически. Новые планы импорта также содержат границы 1 и 5. Ранее импортированные записи не перезаписываются автоматически.
